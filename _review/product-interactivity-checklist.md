# 产品交互性审查规则

> **核心原则：后端跑通 ≠ 产品完成。多 Agent 协作是产品特性，不是开发方法论。**

---

## 一、多 Agent 交互呈现（P0）

### 规则

如果项目使用了多个 Agent/模型协作，**必须把协作链路变成产品界面的一部分**，而不是藏在后台。

### 检查清单

- [ ] 每个 Agent 的输出有独立的 UI 卡片/区块
- [ ] 每个输出标注了来源（如"由 XX Agent 分析"）
- [ ] Agent 之间的协作关系可视化（流程图/泳道图/时序图）
- [ ] 用户能感知到"有多个智能体在协同工作"

### 反例

> 背后有 Hermes + 小浣熊 + 三模型审查在协作，但前端只是一个简单的 HTML 结果展示页。

### 正例

> 预警 Agent → 分析 Agent → 建议 Agent，每个输出独立卡片，下方标注"由预警 Agent 检测"、"由分析 Agent 归因"、"由建议 Agent 生成对策"。

---

## 二、产品完整度（P1）

### 规则

必须覆盖五种界面状态，缺一不可。

### 状态检查清单

- [ ] **加载态**：数据加载时有骨架屏/进度条/loading 动画
- [ ] **空态**：无数据时有引导文案，不是空白页
- [ ] **错误态**：出错时有友好的错误提示 + 重试入口
- [ ] **成功态**：正常展示数据，信息层级清晰
- [ ] **引导态**：首次使用时有引导说明（至少一句话）
- [ ] **边界态**：极端数据（极大值/极小值/0 值/超长文本）不会崩

---

## 三、多维智能性（P2）

### 规则

项目至少覆盖 **2 个以上** 的智能维度，不要只有一个。

### 维度检查清单

- [ ] **检测智能**：发现问题/异常/机会（基本维度，必须有）
- [ ] **归因智能**：解释"为什么"发生
- [ ] **对策智能**：建议"怎么做"
- [ ] **预测智能**：预测"还会发生什么"
- [ ] **对话智能**：支持自然语言问答（至少一问一答）

### 评分标准

| 覆盖维度 | 评级 |
|:---------|:----:|
| 仅 1 个 | 🔴 不足 |
| 2-3 个 | 🟡 合格 |
| 4 个以上 | 🟢 优秀 |

---

## 四、视觉叙事（P3）

### 规则

产品视觉风格应传递领域感，不只是通用 demo。

### 检查清单

- [ ] 配色方案与领域相关（如航运→蓝色系，金融→金色系）
- [ ] 图标/插图与领域相关
- [ ] 演示视频在开发中期（而非最后一天）就开始规划
- [ ] 有至少一个"让人记住"的视觉记忆点

---

## 五、时间节点约束

> 在项目的前 **20% 时间**里，就把以上四章的规划完成——而不是后端做完了才贴前端壳。

### 项目阶段检查点

| 阶段 | 占比 | 必须完成的规划 |
|:-----|:----:|:--------------|
| 启动期 | 0-20% | 多 Agent 可视化方案 + 五种状态覆盖计划 + 视觉方向 |
| 开发中期 | 20-60% | 演示视频脚本 + 至少 2 个智能维度跑通 |
| 收尾期 | 60-100% | 交互打磨 + 视觉统一 + 边界异常处理 |
