## Slide 4 — 项目背景（核心页）

**P: 必须**

### 核心信息

| 要素 | 内容 |
|:-----|:-----|
| **做什么** | 跨境物流异常预警与发货决策情报系统 |
| **解决谁的问题** | 跨境电商物流运营人员（中小卖家 / 货代 / 物流专员） |
| **什么痛点** | 每周花 3-4 小时查运价、算 Excel、写建议——重复劳动、容易出错、依赖个人经验 |
| **为什么值得做** | 中国跨境电商年出口超 2 万亿，物流成本占 15-30%，运价波动可直接吃掉利润 |

### 文案草稿

> 一个 5 人跨境电商团队，每周物流专员需要查 5 个网站、算 4 条航线运价、换算汇率、叠加附加费、判断发货时机——耗时 3-4 小时，且完全依赖个人经验。
>
> 舱路雷达把这个流程自动化：输入 CSV → 自动计算 → 输出预警 + 建议 + 报告，**10 分钟完成**。

### 关键数字

- 人工耗时：**3-4 小时/周**
- 系统耗时：**10-20 分钟/周**
- 效率提升：**9-24 倍**
- 监测航线：**4 条主力 + 综合指数**
- 数据跨度：**30 周连续**

### 视觉建议

左边放「人工流程 vs 系统流程」对比图，右边放核心数字大字。

## Slide 10 — 技术方案（关键页，必须体现小浣熊）

**P: 必须**

### 整体架构

```
┌─────────────────────────────────────────────┐
│              数据输入层                      │
│  SCFI CSV / CCFI CSV / 汇率 / 布伦特 / BDI  │
│              (shared/ 目录)                  │
├─────────────────────────────────────────────┤
│              计算引擎 (compute.py)            │
│  data_loader → metrics → scenarios → output │
│        config.yaml 驱动 / Z阈值可调          │
├─────────────────────────────────────────────┤
│              输出层 (5 JSON)                 │
│  metrics.json / history.json / scenarios    │
│  decisions.json / indices.json              │
├─────────────────────────────────────────────┤
│              展示层 (dashboard.html)          │
│  核心指标链 / 走势图 / 预警 / 热力图         │
└─────────────────────────────────────────────┘
```

### 🔑 办公小浣熊的使用

| 小浣熊功能 | 在舱路雷达中的具体使用 |
|:----------|:-----|
| **数据分析 Skills** | 前期数据清洗、异常值检测、缺失值插值策略生成 |
| **代码生成 Skills** | `compute.py` 代码编写与重构（v5→v6 架构升级） |
| **文档处理 Skills** | Markdown 报告生成、CSV 格式标准化 |
| **代码审查 Skills** | `compute.py` v6.3 三方审查（Kimi+LongCat+Flash 29 条缺陷修复） |
| **文件管理** | 项目文件通过 `~/小浣熊/` 工作区管理，Git 21 次提交 |
| **会员算力** | raccoon-chat-ml-5-5 提供代码生成和审查的底层 LLM 能力 |

### 技术亮点

> 1. **config.yaml 驱动**：Z 分数阈值、季节判断、质量降权全部参数化，不硬编码
> 2. **数据质量分层**：A/B/C/PENDING 五级标注，演示补全绝不伪装真实数据
> 3. **三方交叉验证**：SCFI + CCFI + WCI + FBX 四个指数互相印证
> 4. **复跑机制**：每周替换 CSV 输入 → 运行 compute.py → 5 JSON 输出自动更新

上半部分放架构流程图，下半部分放「小浣熊使用」6 个卡片。
