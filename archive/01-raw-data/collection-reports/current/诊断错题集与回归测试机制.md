# 舱路雷达｜诊断错题集与回归测试机制

## 目的

本文件用于沉淀采集过程中的失败路径、限制、原因猜测、可替代方案和后续解决办法。它不是一次性结论，后续如果某个问题被解决，应补充 `resolved_method`、更新 `status`，并记录解决条件。

## 使用原则

1. 不把失败简单视为“不可做”，要记录症状、可能原因、替代方案。
2. 不绕过付费、登录、授权或反爬限制。
3. 空闲时可以回归测试，但不能让错题测试阻塞主线采集。
4. 一旦找到稳定解决办法，必须回写错题集。
5. 对准确度有风险的路径，默认宁缺毋滥。

## 错题集文件

- `诊断错题集.csv`

## 状态口径

- `open_monitor`：保留观察，后续有条件再测。
- `abandoned_as_primary`：放弃作为主路径，但可在特殊条件下辅助。
- `resolved`：已解决，必须填写 `resolved_method`。

## 建议的空闲回归测试节奏

每次主线采集完成一批后，如果有空闲，再测试：

1. 上海航运交易所单期页是否能稳定回显目标日期。
2. web_search 是否恢复稳定。
3. 国际船舶网旧页面是否可通过浏览器或移动端访问。
4. SAFE/ChinaMoney 是否可免登录导出区间汇率。
5. Brent历史行情是否可通过东方财富/新浪稳定导出。

## 当前结论

当前主路径仍为：

> 逐周采集公开网页正文/截图证据 → 高置信草稿 → 人工/程序复核 → 合并主数据。

错题测试只用于优化路径，不替代主线。
