【细则名称】船公司公告自然周归类与事件抽取细则

【核心原则】
1. 公告按"发布日期"归入自然周，用于"当周情报汇总"。
2. 公告的"生效日期"单独记录，用于后续"事件-运价关联分析"。
3. 一份公告可能跨越多个自然周（如周五发布、下月生效、持续停航），必须拆成多条记录。

【自然周归类规则】

规则1：按发布日期归周
- 公告PDF或网页上标注的发布日期（Published Date / Release Date）→ 决定归入哪个week_id。
- 如果只有"生效日期"没有"发布日期"，则生效日期前推3-7天合理推断为发布周，并在notes标注"发布日期推断"。
- 示例：
  * 公告发布于2026-05-20（周三）→ 归入2026-W21
  * 公告发布于2026-05-23（周六）→ 归入2026-W21（周六属于该自然周）

规则2：生效日期单独记录
- 在事件表中保留effective_date字段（精确到日）。
- 生效日期可能与发布日期跨周，这是正常的，不强制对齐到同一周。
- 示例：
  * 发布于W21（5月20日），生效于6月1日（W23）→ 发布周=W21，生效日期=2026-06-01

规则3：持续事件拆周记录
- 停航、空班、附加费生效期可能持续多周。
- 处理策略：
  * 如果是"一次性事件"（如GRI涨价、单周停航）：1条记录，week_id=发布周。
  * 如果是"持续事件"（如PSS从6月1日持续到9月30日）：
    - 主记录：week_id=发布周，event_type="PSS announced"，effective_date=2026-06-01，expiry_date=2026-09-30
    - 可选：在分析阶段，如需按周展示PSS影响，再衍生出每周一条的"影响标记"，但原始事件表保持1条。

规则4：同一自然周多公告处理
- 同一船公司同一周可能发布多份公告（如同时发GRI和PSS）。
- 每条公告独立成记录，不合并。
- 同一船公司同一周超过3条公告时，在notes字段标注"该周公告密集，建议关注"。

规则5：跨周生效的关联分析准备
- 在后续事件关联分析中（批次4B/批次5），匹配规则为：
  * 公告生效日期 ±7天 内的运价跳升 → 视为"高置信关联窗口"
  * 公告发布日期 ±3天 内的运价跳升 → 视为"中等置信关联窗口"（可能是预期效应）
- 这个窗口规则在分析阶段使用，采集阶段只负责记录准确日期。

【事件类型标准化编码】
采集时必须统一为以下编码，禁止自由发挥：

| 原始表述 | 统一编码 | 说明 |
|:---|:---|:---|
| General Rate Increase / GRI / 综合费率上涨 | GRI | 基础运费普涨 |
| Peak Season Surcharge / PSS / 旺季附加费 | PSS | 旺季征收 |
| Bunker Adjustment Factor / BAF / 燃油附加费 | BAF | 燃油成本调整 |
| Low Sulphur Surcharge / LSS / 低硫附加费 | LSS | 环保低硫燃油附加 |
| Blank Sailing / 停航 / 空班 | BLANK | 航线取消 |
| Port Omission / 跳港 / 挂港取消 | OMIT | 跳过某港 |
| Port Congestion / 港口拥堵 | CONG | 港口拥堵通知 |
| Equipment Imbalance / 空箱不平衡 | EQUIP | 设备/空箱问题 |
| Force Majeure / 不可抗力 | FORCE | 罢工、战争、天气等 |
| Rate Restoration / 费率恢复 | RESTORE | 船公司主动调价 |
| 其他未归类 | OTHER | 需在notes中说明原文 |

【输出格式：船公司公告事件表】
文件名：原始_船公司公告_事件表.csv
字段规范：
week_id, carrier, event_type, event_desc, publish_date, effective_date, expiry_date, affected_route, fee_usd, fee_currency, unit, source_pdf, source_url, verification_level, notes

字段说明：
- week_id：发布日期所在自然周（如2026-W21）
- carrier：船公司标准化简称（马士基/MSC/中远/ONE/长荣）
- event_type：统一编码（见上表）
- event_desc：原文摘要（50字以内）
- publish_date：发布日期（YYYY-MM-DD）
- effective_date：生效日期（YYYY-MM-DD，如未明确则留空）
- expiry_date：失效日期（如有，否则留空）
- affected_route：影响航线代码（如CN-EUR，如未明确则留空）
- fee_usd：费用金额（统一换算为USD，如原文是EUR或百分比，在notes注明换算依据）
- fee_currency：原始货币（USD/EUR/CNY/百分比）
- unit：单位（USD/TEU, USD/FEU, USD/箱, 百分比）
- source_pdf：PDF文件名
- source_url：网页URL
- verification_level：A（官网PDF）/ B（官网网页）/ C（行业媒体转载）
- notes：任何需要说明的额外信息

【采集执行步骤】
步骤1：逐家船公司搜索
对马士基、MSC、中远海控、ONE、长荣，分别访问官网Newsroom。

步骤2：筛选近3个月公告
只采集2026年3月至5月（或你需要的时间段）的公告。

步骤3：下载/保存
- 有PDF的下载PDF，记录文件名。
- 只有网页的，复制正文保存为.txt，记录URL。

步骤4：逐份抽取字段
按上述字段规范，从每份公告中提取信息。

步骤5：周归类与编码
- 确定发布日期 → 计算week_id
- 确定事件类型 → 映射统一编码
- 费用如有多种箱型，优先记录40尺柜（FEU）标准，TEU数据在notes注明

步骤6：交叉检查
- 同一事件是否被多家船司同时公告（如行业性GRI）→ 在notes标注"行业同步"
- 费用金额是否与历史同类事件偏离>30% → 在notes标注"金额异常，建议复核"

【特别注意事项】
1. 公告中的"生效日期"和"发布日期"必须分开记录，不可混为一谈。
2. 如果公告写"自6月1日起适用于所有亚洲出口货物"，affected_route填"CN-ALL"或留空（视航线字典定义），在event_desc中详述。
3. 百分比形式的费率上涨（如"GRI +$200/TEU"）直接录入fee_usd=200；如果是"上调10%"，fee_usd留空，fee_currency填"百分比"，notes写"原文为上调10%，基准费率未知"。
4. 如果某份公告涉及多条航线，优先拆分为多条记录（每条航线一条），如确实无法拆分，affected_route填"MULTI"，notes列出所有航线。
